# Phase 11 plan — map-grounded structure

Implementation plan for phase 11 of [the osr-forge spec](spec.md), the third phase of [the improvement arc](improvement-spec.md): the printed map becomes extraction input for the first time. One new model stage reads each level's map page(s) and proposes room-key adjacency pairs, doors on those pairs, and the entrance — and nothing more; one deterministic reconciliation merges those proposals with prose connections inside geometry synthesis; every adoption and every disagreement carries a flag; one implementation PR, one fixture re-record, one live double sweep. The milestone: **every map/prose disagreement in the committed corpus is a visible report item, and the phase 9 door, transition, entrance, and connection metrics — especially JN1's edge precision — are re-measured with the map in play**, the PR carrying the reading of whether reconciliation moved them beyond the bands — the phase 12 go/no-go evidence.

Six facts shape everything:

- **The survey already records the map pages.** `SurveyLevel.map_pages` has fed the content pass's compass hint and the previews index since phase 6, and it is complete where it matters: over the phase 10 retained pair's 44 surveyed levels, 43 carry exactly one map page and one (sweep 2's JN2 `r6-dragon-harbor` level 1) carries two — never zero. The map stage plans its requests off the existing survey cache — no survey prompt or schema change, no survey fixture re-record — `page_request_parts` already builds the text+image parts every page-consuming request must use, and the multi-page case is handled by construction (`map_pages` is a tuple; the request sends the set).
- **The scorer pre-committed the seam, and the hard check is free.** `_edge_facts`'s docstring: "Phase 11 reroutes this function through its deterministic reconciliation without touching either consumer's semantics"; `EntranceMetrics`'s: "the pre-change baseline phase 11's map-proposed entrance will be measured against through the same seam." Both the connection F1 and the door family already consume one edge-fact derivation, and the entrance family reproduces geometry's selection inline. The standing phase 10 pair (retained at `~/osr-forge-measurement/phase10/`) has no map caches, so the rerouted scorer must reproduce the committed board byte-for-byte — the phase 9 hard-check discipline, re-run.
- **Cycle edges are not realized at all today — that is the door-drop mechanism.** `_place_level` routes corridors only for BFS tree edges; a connection that closes a cycle (or whose child was re-anchored) gets no corridor, no open edges, and its stated door drops with `connection_ambiguous:door to <key> not placed` — a printed loop plays as a tree, silently. Routing every resolved edge is the rescue the improvement spec names ("the map gives them a wall to land on") and it is a base-synthesis change: it reshapes existing goldens even with no map cache present, deliberately, and it is the one phase 11 behavior that reaches workdirs converted before the stage existed.
- **Prose absence versus assertion is already doctrine, and the precedence rule generalizes it.** Geometry's upgrade clause pins "the default `passage` is an absence, not an assertion." The reconciliation rule extends it across evidence sources: **a stated prose fact survives any map conflict, flagged; a prose absence fills from the map, flagged as adopted; agreement is silent.** One corner recorded: geometry's first-stated-mechanism merge and the scorer's either-side door dedup disagree on a two-mention stairs-then-door edge — a pre-existing, phase-9-measured asymmetry the shared merge deliberately does not unify, because unifying it would move existing metric semantics.
- **The entrance heuristic is a zero-evidence guess, and phase 9 measured exactly where it fails.** First listed area of the lowest-numbered non-empty level — right 13/14 on JN1, 5/6 on JN2, 0/1 on B4, failing precisely on the cases truth authors flagged as judgment-worthy (vestibule-fed galleries, map-labeled entries). A resolvable map proposal therefore wins over the heuristic (evidence over position), flagged whenever the two differ; the selection becomes one shared function — the `transition_via`/`usable_stat_block` precedent — so the scorer and geometry can never pick differently.
- **The census's first outing prices the flag posture.** Phase 10's census caught the mode-flip alive and also emitted 12 spurious dispute entries in one run — noisy but honest, tuning deferred. The map disputes inherit that posture knowingly: flag-only, no re-roll, no suppression heuristics; the human eyeballs the side-by-side previews index (workstream A, landed in bf34f22) that the improvement spec names as this phase's verification surface.

## Scope

In scope:

- **The map-reading stage.** `Stage.MAPREAD` (value `mapread` — the stage-named-function convention makes a stage named `map` shadow the builtin), positioned between `monsters` and `assemble`: the downstream-most model stage, so `rerun mapread` re-rolls only itself plus assembly, and a map failure preserves the expensive content and monsters caches. Module `src/osrforge/mapread.py`, function `mapread(workdir, provider)`, cache `stages/mapread.json`, request tag `mapread.<dungeon-id>.<level>`, one request per level (mirrors the content cache's addressing; keeps each request's key list unambiguous; no chunked variant — per-level requests are inherently small). Knob `map_reading: Literal["read", "off"] = "read"` owned by the stage. The stage slots into `RUNNABLE_STAGES`, `_MODEL_STAGES`, `_chain_steps`, `KNOB_STAGES` (the drift-guard test covers the pairing), the workdir accessor set, and `survey()`'s on-success clear list (the cache depends on the survey alone; content and monsters don't touch it).
- **The reconciliation module.** `src/osrforge/reconcile.py`: pure, deterministic merge of prose edge facts with map proposals plus the shared entrance selection, consumed by both geometry synthesis and the scorer — the shared-predicate precedent extended from a function to the whole policy.
- **Geometry integration.** Map-only edges join the placement graph; adopted doors realize like prose doors; every resolved graph edge without a realized route — cycle-closing and re-anchored alike, whatever its provenance — gets a post-placement corridor-routing pass so stated doors land; the entrance selection swaps to the shared function, and the entrance level's placement anchor follows the selected entrance area (identical to today's anchor when the heuristic wins, so no-map behavior changes only through cycle routing).
- **The `map_disputed` flag** (additive vocabulary), carrying every adoption, disagreement, and dropped proposal with a detail naming both readings.
- **The scorer reroute**: `stages/mapread.json` read when present (absent tolerated — the `statblocks.json` posture), `_edge_facts` rerouted through the shared merge, the entrance family through the shared selection; the offline hard check on the standing pair.
- **`estimate` learns the stage's cost**; the CLI prints its line.
- **The measurement pass**: the minimod fixture recorded through a targeted leg, goldens re-blessed, the live double sweep with the map in play, both committed scoreboard halves updated, bands refreshed, the phase 12 go/no-go amendment recorded in the improvement spec.

Out of scope, each with its disposition:

- **Room footprints.** Phase 12's schema extension, contingent on this phase's sweep; building the schema now for a contingent phase is the dead accommodation the greenfield discipline forbids (the improvement spec pins this split explicitly).
- **Map-proposed vertical links.** The schema proposes same-level adjacency, doors, and the entrance — transitions stay prose-derived, untouched by construction (per-level requests can't even express a cross-level pair), and the transition metrics are expected flat.
- **Door conditions from the map.** Stuck/locked stay prose-owned; map legends rarely mark them and the truth doesn't assert stuck at all. The map proposes presence and kind (`door`/`secret_door`) only.
- **Census-dispute arbitration.** Phase 10 deferred `survey_disputed` precision tuning "until phase 11's map pass gives a third opinion," but the map stage consumes the survey's structure and cannot independently adjudicate site identity; the deferral stands, re-recorded here.
- **A geometry-realization metric.** Phase 9 named it this phase's territory; the cycle-routing pass makes realization near-total and every remaining failure carries a flag, so a metric would measure an audited residue. Unbuilt until a measured gap demands it.
- **A re-roll on map/prose disagreement.** Flag-only, the census's own v1 posture, for the same reason: a re-roll policy designed against zero observed disagreement distributions is speculation.
- **Sub-stage progress events.** Workstream A's remaining bullet; not a phase 11 dependency (the stage emits standard stage-level events through the existing chain).

Spec impacts, applied with the implementation PR:

- **`docs/spec.md`** § Pipeline: seven stages, "stages 1–4 call the model," the map-reading stage's own entry, and the geometry stage gaining reconciliation, cycle routing, and the shared entrance selection; § The workdir: `stages/mapread.json`; § Extraction report: the flag sentence gains `map_disputed`; § Configuration: the `map_reading` knob; § Testing and evals: the edge families' fact source becomes the reconciled set; § Open questions: vision-first geometry narrows to footprints (phase 12).
- **`docs/improvement-spec.md`**: no plan-time change; the phase 12 go/no-go reading lands there as an amendment with the implementation PR's sweep, before any phase 12 plan is written.

## Work items

### 1. The stage — `contracts/stages.py`, `mapread.py`, wiring

- Contract models (frozen, `extra="forbid"`, no stage-module imports): `MapEdgeProposal` (`a: str`, `b: str`, `door: Literal["none", "door", "secret_door"] = "none"`), `MapLevelReading` (`dungeon_id`, `level_number`, `map_pages` — the pages actually sent, provenance — `status: Literal["read", "unread"]`, `unread_reason: str | None`, `proposals: tuple[MapEdgeProposal, ...]`, `entrance_key: str | None`), `MapReading` (`schema_version`, `map_reading` knob echo — the `StatBlocks.custom_monsters` precedent, so assembly reads the cache, never the knob — and `levels`). **Keys cache as answered, raw**: endpoint resolution happens at reconcile time in deterministic code, so a reconciliation-policy fix never strands a recorded fixture.
- `Stage.MAPREAD` inserts between `MONSTERS` and `GEOMETRY` — a new key in `run.json`'s stage table (minted complete by `preprocess()`), additive within the schema version.
- The request: system prompt pinned at intent level — propose adjacency only between the provided printed keys, two keyed areas adjacent when the map joins them directly by a door, opening, or passage *or* through unkeyed passage in consecutive order along it (the truth convention's own wording, so the proposal universe and the yardstick agree); a door only where the map marks one, `secret_door` per the map's legend; the entrance only where the map labels the way in; propose nothing that cannot be read. Parts: one text part naming the dungeon, level, and the keyed-area list in survey order (printed forms via `source_label or key`, the census's printed-form recovery precedent), then `page_request_parts` over the level's unblanked map pages. **No content-stage output rides the request** — the map read is an independent second opinion, and feeding it prose connections would let one instrument contaminate the other. Schema: flat, tolerate-and-flag (the `AreaConnection` posture) — `adjacencies` (a/b/door) plus nullable `entrance`.
- Stage behavior, per level: pages in `blank_page_renders` are excluded from the sent set (preprocess emitted them as blank white PNGs — sending one buys nothing and a blank read as an empty map would dispute every prose edge); no map pages at all → `unread:no_map_pages`, no request; a nonempty `map_pages` whose every page is blanked → `unread:pages_blanked`, no request; a level with two or more keyed areas whose answer proposes zero adjacencies → `unread:empty_reading` (a degenerate read must not assert map silence against the whole level), discarding its entrance too; a single-area level keeps a zero-pair reading and its entrance proposal. Under `map_reading: off` the stage completes writing the knob-echoed cache with zero levels. Usage accrues through `track_stage` as one stage.
- `tools/extract/run_extraction.py`'s fabricated completed-stage tuple gains `MAPREAD`; `docs/contributing/architecture.md`'s stage table gains the row.

### 2. `reconcile.py` — the shared merge and entrance selection

- `merge_level_edges(prose, reading, level_keys)`: resolves each proposal endpoint exactly-then-slug (geometry's `_resolve_target` rule), drops self-pairs and unresolvable endpoints into `dropped` records, dedups duplicate proposals (door beats none, `secret_door` beats `door` — the scorer's more-specific precedent), then merges per undirected pair under the precedence rule with provenance (`both`/`prose_only`/`map_only`) and disagreement details as stable human-readable strings (the `census_disputes` grammar). The rule, enumerated: agreement → silent; map door onto a prose edge with no stated mechanism → adopted, flagged; prose-stated door (or kind, or non-door mechanism) contradicted by the map → prose survives, flagged; prose edge absent from a read map → kept, flagged; map-only pair → adopted as an edge (plus its door), flagged. The `door: "none"` cells, pinned: **a proposed pair's door reading is complete** — the truth convention's own posture (an asserting area's omitted neighbor is an explicit no-door), and the second opinion on prose's weakest door number (precision as low as 0.48) is the point — so a prose-stated door on a pair the map proposes with `door: "none"` is a presence disagreement (prose survives, flagged), while prose with no stated door on that pair agrees silently, whatever its non-door mechanism (the map's vocabulary doesn't carry mechanisms). An `unread` level produces no adoptions and no disagreements — the prose-only path, bit for bit.
- `select_entrance(dungeon, readings)`: heuristic pick (lowest-numbered non-empty level, first listed area); map candidate = the first resolvable `entrance_key` in level-number order; the map candidate wins when present, with a detail naming both picks when they differ; unresolvable proposals drop into the same `dropped` channel, and a *secondary* resolvable proposal (another level also labeling a way in) is neither adopted nor discarded silently — it lands in `dropped` with its own detail, a reviewable oddity under the no-silent-proposals rule. Returns the selected `(level_number, area_key)` plus provenance — the single source both geometry and the scorer consume.
- The prose side of the merge is each consumer's own derivation (geometry's `_GraphEdge` merge; the scorer's `_edge_facts` dedup) — the shared code owns the map-versus-prose policy, not a rewrite of either prose derivation (the recorded asymmetry above stays put). The scorer-side fact gains an internal stated-mechanism marker so the absence test matches geometry's (`via == "passage"` on every mention is the only absence).

### 3. Geometry — the merged graph, cycle routing, the entrance

- `synthesize_geometry` takes the optional `MapReading`, and **both call sites thread it** — `assemble()` and `render_previews()` (the `preview` command re-synthesizes, and its documented guarantee is that previews follow the draft; an unthreaded preview path would silently diverge). A missing cache (a pre-phase-11 workdir) reconciles as no proposals.
- Map-only pairs join the level graph as `_GraphEdge(direction=None, owner=survey-order-first endpoint, via=door kind or None, via_owner=owner when a door is adopted)` *before* component ordering — they can reduce disconnected components and become tree edges. A map door adopted onto an existing prose edge sets `via`/`via_owner` the same way (`via_owner` = survey-order-first endpoint — the map has no stating area, so one pinned convention covers both adoption shapes); `_door_edges` skips a `via_owner`-less edge by design, so the sketch is load-bearing. Adopted doors realize on the owner's wall exactly like prose doors, conditions `False` (the map cannot state them).
- The cycle-routing pass, after BFS placement: every resolved graph edge without a realized route routes a corridor from the owner room to the target room — BFS shortest path, free cells and existing corridor cells traversable (junctions are legal and `_open_edges` already opens them), all other rooms blocked, expansion and tie-break orders pinned for determinism, the path registered in **both** `placement.paths` (so `_open_edges` opens the corridor and its cells render) and `edge_paths` (so `_door_edges`'s rule (a) lands the stated door) — a door edge on a route `_open_edges` never opened would violate the door-replacement invariant. Success retires the `door to <key> not placed` drop for that edge; genuine failure (a walled-in pair) keeps today's door drop and adds `connection_ambiguous:edge to <key> not routed` for the doorless case — an unrealized connection stops being silent.
- The entrance: the inline heuristic is replaced by `select_entrance`; the entrance level's anchor becomes the selected entrance area (today's `survey_keys[0]` exactly, whenever the heuristic wins). `LevelGeometry` gains the disagreement channels — `(area key, detail)` pairs for edge and entrance disputes, plus module-scope dropped-proposal details — that assembly turns into flags verbatim, the existing `unresolved_connections` pattern.

### 4. Assembly and the report — `map_disputed`

- `Flag.MAP_DISPUTED` (additive; description added to the vocabulary generator's dict, which `KeyError`s on omission). Emission homes, pinned: edge disputes on the survey-order-first endpoint area (one flag per dispute, the detail naming both areas and both readings); the entrance dispute on the *selected* entrance area; dropped proposals (unresolvable keys, secondary entrance proposals) at module scope with the level address in the detail. The detail grammar is the contract — `edge <a>–<b> <reading>`, `door <a>–<b> <reading>`, `entrance map <key>, survey-order <key>`, `entrance also proposed <level>/<key>`, `map names '<key>'; the survey does not` — exact wording pinned at implementation, grammar and homes here.
- Assembly threads the cache into geometry and emits the channels; `report.json` gains no new section — flags are the whole consumer surface (the improvement spec's own scoping), and osr-editor's mirrored vocabulary picks the badge up with its one-file change (workstream C's recorded ask).
- The missing-cache posture, sharpened past the statblocks precedent it leans on: that precedent is airtight only because assembly gates on a completed monsters stage, and `mapread` sits downstream of that gate — so a workdir whose mapread stage **failed** mid-convert also has no cache, and a silent prose-only assemble would hide it. Pinned: assembly errors on a `run.json` mapread entry in `failed` or `running` state, naming `rerun mapread`; a `pending` or absent entry, or an absent cache, reconciles as no proposals (the honest state of a pre-phase-11 workdir and of the fabricated test workdirs, which mint every unneeded stage `pending`). The guard is assembly's alone by design: `render_previews` reads no `run.json`, so `preview` after a failed mapread renders prose-only previews — harmless (there is no draft to diverge from; assemble errors loudly), and guarding it would add a `run.json` dependency to the pure preview path for no real protection.

### 5. The scorer — the seam reroute and the offline hard check

- `score_workdir` reads `stages/mapread.json` when present; absent is the honest state of an older workdir, never an error (the `statblocks.json` posture). `_edge_facts` derives prose facts as today, then applies `reconcile`'s merge with the pairing level's reading, endpoints resolved and filtered to matched slugs; merged pairs flow through the unchanged asserted-universe gates, so map-only edges and map-adopted doors enter exactly where truth asserts. The entrance family calls `select_entrance` in place of its inline reproduction.
- The offline hard check, phase 9 style: re-score the standing phase 10 pair (sweep-1 workdirs through `rescore`, sweep-2 through plain `score`); with no map caches present every family must reproduce the committed board byte-for-byte — any drift is a scorer bug, not noise. Recorded in the amendment; bands untouched by this leg (the live sweep refreshes them). The pinned JN1 CI baseline is the same check in CI form: the committed caches carry no map cache, so its values must not move and are asserted, not re-blessed.

The estimate stays a rough gate, as its docstring already says.

## Amendments (implementation)

Where the implementation found the plan silent, the pinned calls:

- **A fourth unread reason, `no_keyed_areas`.** The plan's per-level behavior table didn't cover a surveyed level with zero keyed areas: there are no printed keys to propose between, so the stage makes no request and records `unread:no_keyed_areas` — the `no_map_pages` posture, same shape.
- **Shared doorways collapse, deliberately.** Routed corridors traverse existing corridor cells (junctions are legal), so two or more doored routes can leave their stating room through the same wall edge; their doors collapse to the one physical doorway, with the last edge in graph order pinning the surviving `DoorSpec` — deterministic, and the geometry `edges` override is the remedy if the collapsed kinds genuinely differ. Nothing drops and nothing flags — every connection is realized, and the doorway sits on the stating room's wall (the dense-hub unit test pins the shape and the survivor: room 88's three stated doors all leave through one edge). The alternative — forcing distinct exits — would reject the junction legality the routing pass rests on.
- **The missing-cache gate reads the cache whenever the file exists.** The plan enumerated `failed`/`running` (error), `pending`/absent entry, and absent cache; it didn't name the pending-entry-*with*-cache state, which no real workdir produces. Pinned as the statblocks posture verbatim: error on `failed`/`running`, otherwise read the cache when the file exists — the cache is the record.
- **The report's usage total includes the mapread stage**, read with `.get` so a pre-phase-11 `run.json` (no mapread key) still assembles.
- **The minimod mapread fixture records an honest `empty_reading`.** Minimod's map page draws unlabeled boxes — no printed keys — so the live model correctly proposed nothing ("propose nothing that cannot be read"), and the recorded fixture exercises the degenerate-read path end to end; the adoption, dispute, and dropped-proposal paths run through synthetic-cache pipeline tests instead.
